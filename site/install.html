Install guide

Install, configure and remove the Accessibility Scanner

One client extension package brings the scanner and its Objects. The report fragment ships inside it. Nothing runs outside your portal.

Requirements

  • Liferay DXP 2026.Q2 or 2026.Q3, self-hosted, PaaS or SaaS.
  • A current browser for authors: Chrome, Edge, Firefox or Safari.
  • An administrator who can deploy client extensions.

Install

  1. On the Marketplace listing, choose Get App and download accessibility-scanner.zip. Keep the file name as it is: the portal serves the extension at /o/accessibility-scanner/.
  2. Deploy the zip like any client extension.
    • Self-hosted: copy it to the deploy folder in Liferay Home. The portal moves it to osgi/client-extensions.
    • PaaS or SaaS: deploy it through your usual client extension pipeline or the Liferay Cloud console.
  3. Check the result.
    • Site Menu, Content & Data lists Accessibility Scans, Scanned Pages and Accessibility Findings.
    • Site Menu, Configuration lists Accessibility Settings.
    • Edit a content page: the Accessibility button appears in the editor toolbar.

The extension adds one script to every page. It is a small loader that fetches the scanner only in the page editor, the Page Tree and the content editors, and only for signed-in users.

Add the report for your team

  1. Download the fragment collection from your own portal: https://<your-portal>/o/accessibility-scanner/accessibility-scanner-fragments.zip.
  2. Go to Site Menu, Design, Fragments. Open the Options menu and choose Import. Select the zip.
  3. Place the Accessibility Report fragment on a page. Its configuration sets the trend length, the number of pages and the sections to show.
  4. Run a site scan from the Accessibility button in the Page Tree header. The report fills in as soon as the scan ends.

The report reads the scans with the visitor's session. People without permission to view Accessibility Scans see a sign-in hint instead of the data.

Configure each site

Every feature is on by default. To change that for a site, open Site Menu, Configuration, Accessibility Settings and add one entry. Each switch turns something off or adds a check:

  • Hide the panel in the page editor.
  • Disable the published page scan.
  • Disable site scans.
  • Disable checks in the CMS content editor, which reads the setting from the Global site.
  • Disable checks in the Web Content editor.
  • Disable checks in the Blogs editor.
  • Block publishing CMS content with critical issues.

Site scans also follow regular permissions. Only roles with Add Object Entry on Accessibility Scans see the Page Tree button. Site administrators and owners have it by default. To grant or remove it, define permissions on the role under Site Administration, Content & Data, Accessibility Scans.

Upgrade

Deploy the new accessibility-scanner.zip over the old one. The Objects are updated in place and existing scans are kept. Import the fragment collection again from the same URL to get the new report, then propagate the change to the pages that use it.

Uninstall

  1. Remove the client extension. Self-hosted: delete accessibility-scanner.zip from osgi/client-extensions. PaaS or SaaS: remove it from the Cloud console. The scanner stops loading at once.
  2. Remove the Accessibility Report fragment from the pages that use it, then delete the collection in Site Menu, Design, Fragments.
  3. The Objects and the scans they hold stay in the portal, so a reinstall picks up the history. To delete everything, delete the four object definitions in Control Panel, Objects: Accessibility Finding, Scanned Page, Accessibility Scan and Accessibility Setting. This removes their entries for good.

Help

Report problems and ask questions in GitHub issues. The rule documentation explains each Liferay rule and how to fix what it finds.
